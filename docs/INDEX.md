## 2. ADR 索引

| 编号 | 标题 | 状态 | 一句话结论 |
|---|---|---|---|
| 001 | 采用 HyperLPR3 预训练模型，而非自行训练 | 已接受 | 时间预算投给差异化环节；含 YOLOv9-t 三档尺寸的**证伪记录** |
| 002 | 跨语言移植的数值保真策略 | 已接受 | 逆向 `cv2.resize` 定点实现 → 整数比逐通道一致；定位关键点未截断的 1 px 缺陷（MU4158→H468） |
| 003 | 麒麟 8020 端侧部署路径与运行时缺陷 | 已接受（§7 由 004 完成） | MindSpore Lite → NNRT 路径 + FP16 缓冲区声明为 FP32 的缺陷（误差 7.78e18% → 0.015%） |
| 004 | 三后端可用性矩阵、NPU 拒绝边界与跨源隔离实证 | 已接受 | 以 `LANDED=` 实际落点判委托，不看请求后端 |
| 005 | 原生 C++ 流水线、三模型混合后端落点与 GPU 专项复测 | 已接受 | 混合后端落点实测，与 Python 参考逐项对照 |
| 006 | 检测模型上 NPU —— 裁掉 decode，并定位到真正的算子缺口 | 已接受 | 裸 head 导出 → 全图纯 NPU 4.95–5.04 ms；decode 公式 MATCH 0.000061 |
| 007 | NPU 算子约束的真实边界，与按支持清单选模型的路径 | 已接受 | **官方算子清单不作数，先静态扫描**（看 perm/rank，不看算子名） |
| 008 | GPU 终审 —— Vulkan compute 可达 | 已接受 | dlopen `libvulkan.so` → Maleoon 920C（Vulkan 1.3.275，2 条 G+C 队列，fp16 在位）；MS Lite / ORT-Web 路线死 |
| 009 | 检测裸 head 的 C++ decode 落地，与 NPU 数值漂移的量化取舍 | 已接受 | NPU 真在算（L2 对照实锤），但 0.08% 漂移 → 翻字符 → `det=CPU / rec=NPU / cls=CPU` |
| 010 | 端侧演示 300ms 的归因 | 已接受 | 瓶颈不是多线程，是 **letterbox 预处理**（det 79 ms 里推理仅 10–18 ms） |
| 011 | ncnn 接入 App —— 交叉编译、内存 API 陷阱与保真验证 | 已接受 | ncnn CPU 跑通；三套内存 API 语义差异是主要坑 |
| 012 | CANN / HiAI / NNRt 直连路线的评估与「不换」决策 | 已接受 | **现有 NPU 通道就是官方 NNRt 底座**（设备名逐字互证）；CANN 侧门槛是 `.om` 转换器而非权限；NNRt 无 GPU 设备 → GPU 仍只有 Vulkan |
| 013 | CANN 通路以厂商 `.om` 端到端验证通过；缺口收窄为「转换器」 | 已接受（§未完成动作 1 由 014 闭环） | 真 `.om` 全绿（`compat=0`/`build_rc=0`/`run_rc=0`，`out_sum≈1.0` 校验为合法 softmax），稳态 **0.92 ms**；同批 `.ms` 仍被拒 → **差别只有格式**。我们的模型仍上不去，缺 OMG |
| 014 | 「按 NPU 友好度选模型」成立，但换模型不解决落点问题 | 已接受（§边界声明由 015 更正） | 官方判据 `Cin&Cout` 双 16 倍数**可预算**（cls 19.2% ↔ 实测 0.74× 更慢，方向一致）；按判据挑的 LPRNet 真机 `build_rc=0/run_rc=0` **但分区 `NPU:2, CPU:1`**（`ReduceMean` 被拒）→ **NPU 支持性 = 模型 × 工具链 的联合属性**；CANN 维持候选第四后端 |
| 015 | 真值串推翻与 `match=` 语义变更；撤回「相机出帧率即上限」；NPU 数字均属 fp16 条件 | 已接受 | `苏ED5172` 是 rpv3 自身输出而非真值（正确真值 8 字符）；`match=` 正式定义为「与 CPU 基线一致」，**不是**「读对」；精度只能引 `_dataset/real/crops` n=1000；A14「相机上限 15fps / 推理侧非瓶颈」**撤回待复测**；日志补 `req=`/`fallback=`/`vkLayers=` |

## 4. 维护约定

- 新的关键取舍 → 新建 `ADR-0NN-<kebab-title>.md`，**必须**含：状态、日期、前置/后续、问题、决策、证据、边界声明、未完成动作。
- 结论变更**不改旧 ADR 的结论**，新增 ADR 并在旧文头部加「后续：ADR-0NN」指针（现有实践即如此）。
- 数字只在 `_evidence/` 落地后再写进论文/简历/网页；三者数字必须一致。
