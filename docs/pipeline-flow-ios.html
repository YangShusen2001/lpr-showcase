关键
相机出帧率随曝光变化，不是固定值。基准档只取帧不推理：暗场景到达=完成 19.92–20.06 fps、 丢帧 0；明亮场景同档 26.92–27.12 fps、丢帧 0 —— 暗光下自动曝光拉长曝光时间才掉到 20。 而全链路只要 ≈ 28 ms。有车牌时到达 27 / 完成 13 = 推理真跟不上，瓶颈在 det=CPU 12.7 ms。
方法
检测器落 CPU 不是性能选择，是与基线一致性要求：NPU 上 0.08% 的数值漂移经锚点放大后 会翻字符（苏ED5172 → 苏E05172）。 两个限定：① 两端都不是真值（真值 8 字符，见 ADR-015），这条结论是差分命题； ② 漂移只在 NPU-fp16 下测过（addNnrt() 恒传 fp16=true），fp32 从未试。

验收边界

已验
功能：相机实时读到真实车牌。速度：全链路 p50 数字均为真机 release 构建实测。 移植保真：8/8 一致，分类逐位、识别符号级。
部分已验
离线精度已建立基线，相机帧仍未验。 识别器在 1000 张第三方真实人工标注裁剪图上 906/1000 = 90.6% （对照 LPRNet 88.8%，McNemar p=0.1788 → 不换）—— 见 _evidence/A16-real-dataset-accuracy-20260918.md。 但相机逐帧读到的串与静态图基准不是同一张图，不能拿相机画面当精度证据。 速度已验（口径见下）、功能已验、离线精度已验、相机帧精度未验。
已撤回
A14 §4.2.2「相机自己只给 15 fps，推理侧已彻底不是瓶颈」已撤回待复测（ADR-015 §2）： 那档"零推理基准"仍付整帧 NV21→RGBA 转换，且与 A14 §4.1 同场景的 arrive=19.92–20.06 自相矛盾。本页 34.5 / 23.8 / 12.8 fps 一律是服务时间理论值，不得对外称 fps。
口径
历史 30× 基准数字全部在 buildMode=debug（native -O0）下测得， 与 release 数字不能并列比较；同档位跨时段存在热/负载波动。
更正
曾经报出的 34.5 / 23.8 / 12.8 fps 是 1000 / p50(frameMs) 算出的 服务时间理论值，不是吞吐。真实吞吐由基准档确定：20 fps（暗）～ 27 fps（亮）。 那些数字只能用于比较各档位的相对开销。
