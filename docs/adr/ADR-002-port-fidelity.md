# ADR-002：跨语言移植的数值保真策略

- **状态**：已接受
- **日期**：2026-09-17
- **前置**：ADR-001（选定 HyperLPR3 预训练模型）
- **后续**：ADR-015 —— 本 ADR 的 8/8 一致结论**存活**（命题是"两份实现是否相同"），
  但表中的 `苏ED5172` 是 **rpv3 自己的输出**而非人工真值；A16 已判定该样本正确真值为
  `苏ED51712`。引用本表时不得称"真值/正确"，措辞一律用"与参考实现一致"。

---

## 1. 问题

把上游 HyperLPR3 的 C++/Python 实现移植成浏览器端 JavaScript 时，最大的风险不是**报错**，
而是**静默地算出略有不同的数**：

- 报错会立刻暴露，静默偏差不会；
- 偏差点可能在链路末端被放大成完全不同的识别结果；
- 一旦识别结果不同，「移植成功」这个结论就站不住脚。

因此本项目把「**证明移植正确**」当作第一优先级，而不是「先跑起来再说」。

---

## 2. 核心发现

### 2.1 `cv2.resize` 不是浮点双线性插值

OpenCV 的 `INTER_LINEAR` 在缩放路径上走的是**定点实现**：

| 环节 | 行为 |
|---|---|
| 系数精度 | 11 位（`COEF_BITS = 11`, `COEF_SCALE = 2048`） |
| 水平趟 | 产出**未右移**的整数中间结果 |
| 竖直趟 | 单次合并舍入 `(v + 2²¹) >> 22` |
| 边界 | 越界索引钳制到 `size - 1` |

直译浮点公式（`w0*a + w1*b`）会产生**系统性的 +1 LSB 偏差**，在 320×320 的 letterbox 张量上表现为
几千个通道值整体偏高。这正是最初 JS 侧检测结果与 Python 不一致的根因。

**验证方式**：构造单位冲激输入，反推核系数。观测到 `247.03 → 247`、`7.97 → 8`，
与「11 位系数 + 单次舍入」的预测完全吻合。

### 2.2 关键点必须在测量四边形之前截断

上游 `multitask_detect.py` 对四个关键点先做 `.astype(int)`，**再**用整数角点去量四边形边长、
决定矫正窗口尺寸。若移植时保留浮点关键点：

- 裁剪窗口整体偏移最多 1 px；
- 对小车牌足以让识别结果从 `MU4158` 变成 `H468`。

**修复**：新增 `truncateMarks(row)`，在 `runPipeline` 中强制路由，与上游逐行对齐。

### 2.3 残余误差有确定上界，且不影响输出

当缩放比不是整数时，仍存在少量 ±1 LSB 差异。以 `scene-2.jpg`（1920→320，缩放比 3.5625）为例：

```
通道总数          307200
差异通道数         11753   (3.83%)
最大绝对差         3.92e-3 (即 1/255)
差异符号           全部为 +1
识别结果           py = 藏DT5022   js = 藏DT5022   ✓
```

经 135 个目标尺寸扫描（比较 5.00×10⁶ 像素）推翻了「残差随源坐标小数部分变化」这一自然假设：
按小数坐标分箱后比例是**平的**（二十个箱全部落在 18.3%–25.0%，最大值出现在 11 位系数量化取整误差
最大的 0.50–0.55 处，而非一条上升斜坡）；改按**垂直方向缩放比例**拆分则立刻分开 —— 垂直比例恰为 1 时
不一致像素仅 **0.113%**，不为 1 时达 **29.108%**。即残差由**第二趟（垂直趟）是否携带小数系数**决定
（垂直比例为 1 时其系数恰为 `(2048, 0)`，两种实现退化为同一次取整），而非小数坐标，
这**无法在 JS 侧确定性复现**。

---

## 3. 决策

**接受「整数缩放比下逐通道一致 + 非整数缩放比下 ≤1 LSB 且有明确上界」的保真度目标，
不再追求非整数缩放比下的位级一致。**

三条支撑理由：

1. **误差有界**：残余差异被限制在 1 个量化级（1/255），且符号单一，可量化、可陈述。
2. **输出无关**：全部 8 个测试样本的识别字符串与 Python 参考一致，颜色分类与检测分数逐位一致。
3. **继续追索的边际收益为负**：要精确复现 OpenCV 垂直趟的定点累加顺序需逆向具体指令序列，工作量与收益严重不成比例；
   而「承认边界并量化它」在工程评审中比「声称完全一致但无法解释残余」更可信。

### 配套工程决策

| 决策 | 理由 |
|---|---|
| 算法层零依赖（只吃 `{data,width,height}` 缓冲区） | 同一份代码可在浏览器与 Node 中运行，便于与 Python 逐字段比对 |
| 线程数自适应（`isolated ? min(cores, forced) : 1`） | 多线程 WASM 需 SharedArrayBuffer → 需 COOP/COEP 响应头。静态托管不提供 → 自动退回单线程；鸿蒙壳与本地 `serve.mjs` 注入头后自动吃满。**ADR-004 §5.4 实测：6 线程最优，端到端 1.5×** |
| 模型与 `.wasm` 全部自托管 | 消除 CDN 依赖，页面可在离线环境演示 |
| 越界索引一律钳制 | 1 像素宽的输入会触发 `sy + 1` 越界（已实测崩溃） |

## 4. 验证方法学

```
┌─────────────────────────┐        ┌──────────────────────────┐
│  Python 参考实现         │        │  浏览器端移植实现          │
│  tools/hlpr_reference.py │        │  assets/js/pipeline.js   │
└───────────┬─────────────┘        └────────────┬─────────────┘
            │ 导出中间量                         │ 导出中间量
            ▼                                    ▼
   _evidence/det_dump.json        _evidence/web__verify_html.json
            └──────────────┬─────────────────────┘
                           ▼
              tools/compare_dumps.py
                           ▼
              _evidence/fidelity_report.txt
```

比对字段：letterbox 参数 → 输入张量首/中段 → 检测器原始输出行 → 检测框 → 关键点 →
裁剪尺寸 → 裁剪 RGB 和 → 识别字符串 → 识别置信度 → 检测分数 → 颜色分类。

浏览器侧由无头 Chromium 驱动（`tools/web_check.mjs`），中间量由页面通过 `window.__RESULT` 发布，
经 `fs.writeFileSync(..., 'utf8')` 直接落盘 —— 避免 PowerShell 管道按遗留代码页重解码而损坏中文。

## 6. 已证伪的路线（不再重试）

| 尝试 | 结果 |
|---|---|
| 浮点双线性直译 | ❌ 系统性 +1 LSB，识别结果不一致 |
| 「水平趟 >>11、竖直趟 >>11」两次舍入 | ❌ 307200 通道中 53646 个不符 |
| 单一布局在多个缩放比上同时拟合 | ❌ 在 scale=6.0 上「完全一致」的布局在 scale=3.5625 上失败（11753 个通道不符）→ 说明不存在统一可复现的定点布局，判定为 SIMD 实现细节 |

---

## 7. 后果

**正面**：项目从「移植了一个能跑的车牌识别」升级为「移植了一个**可证明正确**的车牌识别」。
这条主线直接构成论文与简历的核心贡献点，且全部数字可追溯到本仓库文件。

**负面**：非整数缩放比下无法声称位级一致。缓解方式是**主动量化并公开边界**，而不是回避。
